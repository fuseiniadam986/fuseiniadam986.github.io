香港服务器迁移时 DNS 怎么切换？TTL、验证与回退

DNS 切换看似只是修改一条记录，实际还涉及缓存时间、旧站数据同步、证书、回调白名单和回退窗口。准备充分可以显著减少中断。

拿现有方案来核对

扫码发送业务情况、现有配置或报价截图，聚搜云帮你整理还需要问清楚的项目。

先看判断重点：
  • 切换前提前评估并调整 TTL
  • 使用本地解析验证新服务器完整功能
  • 切换期间保持旧站可用并同步关键数据
  • 明确监控指标与回退触发条件

先把需求放进同一张表

阶段主要动作验证重点
准备盘点记录、降低 TTL解析权限和证书
预检hosts 或测试域名访问页面、接口和回调
切换修改记录并持续监控多地解析与业务日志
收尾保留旧站后再下线无旧流量和数据遗漏

不要在切换当天才降低 TTL

递归 DNS 和客户端可能缓存旧记录。提前调整可以缩短后续传播时间，但实际缓存行为仍可能存在差异，应保留足够的双站运行窗口。

先绕过公共 DNS 验证新站

使用 hosts 或测试域名检查 HTTPS、静态资源、数据库连接、上传、邮件、支付回调和管理后台，避免把应用故障误判为 DNS 问题。

用业务指标决定是否回退

约定错误率、关键功能、数据一致性和响应时间的阈值。达到条件时按预案恢复旧解析，并处理切换期间产生的数据。

采购或调整前核对清单

  • TTL 和切换时间
  • 证书与第三方白名单
  • 新旧数据同步
  • 监控与回退条件
